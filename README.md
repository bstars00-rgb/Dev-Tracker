# OHMY Dev Tracker

한 페이지짜리 **읽기 전용** Dev Tracker 화면. 엑셀이 원본이고, 이 화면은 그걸 보기 좋게 보여줄 뿐입니다.

- 로그인 없음, 데이터베이스 없음, 서버 없음
- `index.html` 더블클릭하면 바로 열림 (인터넷 연결도 불필요)
- GitHub Pages로 자동 배포 — 팀은 링크 하나만 있으면 됩니다

**링크:** https://bstars00-rgb.github.io/Dev-Tracker/

---

## 업데이트 (엑셀이 원본)

### 방법 A — 엑셀만 바꿔서 푸시 (권장)

1. `data/Dev_Schedule.xlsx` 를 최신 파일로 교체 — **파일명은 그대로**
2. 커밋 & 푸시

GitHub Actions가 변환하고 배포합니다. **Node.js 설치 필요 없습니다.**
1~2분 뒤 링크에 반영됩니다. 진행 상황은 저장소 **Actions** 탭에서 볼 수 있습니다.

### 방법 B — 올리기 전에 로컬에서 확인

1. `data/Dev_Schedule.xlsx` 교체
2. **`update.bat` 더블클릭** → 변환되고 화면이 자동으로 열림
3. 확인되면 커밋 & 푸시

이 방법은 Node.js가 필요합니다 ([nodejs.org](https://nodejs.org) LTS). `update.bat` 이 첫 실행 때 안내합니다.

> **엑셀 규칙:** 파일명 `Dev_Schedule.xlsx`, 시트명 `Dev Tracker`, 헤더 3행.
> 컬럼명이 바뀌면 [`scripts/build.mjs`](scripts/build.mjs) 맨 위 목록만 고치면 됩니다.
> 시트가 깨지면 Actions가 배포를 막고 에러로 알려줍니다.

## 최초 1회 설정

저장소 **Settings → Pages → Source: GitHub Actions** 로 지정.
그 다음부터는 푸시할 때마다 자동입니다.

원본 엑셀은 배포 산출물에서 제외되므로 사이트에서 직접 다운로드되지는 않습니다.
다만 저장소가 Public이면 저장소 자체를 통해 접근할 수 있습니다.

사내에서만 쓰고 싶으면 이 폴더를 공유드라이브에 복사해도 똑같이 동작합니다.
화면에 필요한 파일은 `index.html`, `styles.css`, `app.js`, `i18n.js`, `data/tracker.js` 다섯 개뿐입니다.

## 화면 구성

우측 상단 **한국어 / English** 로 전환됩니다. 선택은 브라우저에 저장되고, 처음 방문이면 브라우저 언어를 따릅니다.
파트너명·Status·Category 같은 시트 값은 원본 그대로 두고 인터페이스만 번역합니다.

### Dashboard 탭

**카드 9장** — 값 · 전체 대비 비중 · 구성 막대 · 한 줄 해설. 클릭하면 해당 조건으로 필터된 목록으로 넘어갑니다.

| 카드 | 뜻 | 해설에 뜨는 것 |
|---|---|---|
| 전체 | 시트 전체 | 최다 상태와 건수 |
| High Impact | **매출·물량 기여가 큰 건** (리스크 아님) | 미착수 / 진행 중 / 완료 분해 |
| 완료 (Live) | 라이브 완료 | 단계 날짜로 계산한 평균 소요일 |
| 개발 착수 대기 | SLA 완료 ~ 킥오프 예정 | OHMY 직접 / 파트너 / 스위칭 분해 |
| 개발 진행 중 | 구현 ~ 오픈 준비 | 같음 |
| 스위칭 경유 | TGX·SHIJI 등 경유 | 플랫폼별 건수 |
| OHMY 공수 Full | 우리가 100% 붙는 건 | 그중 진행 중 건수 |
| 손이 필요함 | 방치·무기록 | 가장 오래 조용한 건 |
| 90일+ 방치 | 3개월 이상 | 최장기 건 |

### 공수 × 임팩트 4분면

OHMY 개발 공수(시트의 `OHMY Dev Load`)와 매출·물량 기여(`Biz Impact`)를 교차한 분류입니다.
상자를 클릭하면 그 분류만 목록으로 넘어갑니다.

| | 임팩트 **강함** | 임팩트 **약함** |
|---|---|---|
| **공수 적음** | **즉시 착수** — 적게 넣고 크게 먹는 건. 최우선 | **여유 시 처리** — 부담 없지만 급하지도 않음 |
| **공수 많음** | **전략 투자** — 할 가치 있음. 일정·인력 사전 배정 | **근거 필요** — 공수는 큰데 기대 효과가 안 보임 |

`근거 필요`를 "하지 말 것"으로 하지 않은 이유: 전략적으로 해야 하는 경우가 실제로 있습니다.
못 박는 대신 **진행하려면 이유를 대라**는 요구로 두는 게 의사결정에 쓰입니다.

판정 기준: 공수 많음 = `Full` 또는 `Half` · 임팩트 강함 = `High`.
**`Mid`와 빈칸은 모두 "약함"으로 갑니다.** 지금 108건 중 93건이 Impact 미기재라
`근거 필요` 26건 상당수는 실제로는 그냥 미기재일 수 있습니다 — 패널 아래에 그 사실을 명시해 뒀습니다.
시트의 Biz Impact를 채우는 게 이 화면을 가장 크게 개선하는 방법입니다.

### 개발팀 관점 · 지금 할 일

대시보드의 핵심 패널입니다. **현재 단계 × OHMY 개발 공수 × 스위칭 경로**를 조합해 다음 액션을 뽑습니다.

**구현 경로 판정**

| 조건 | 경로 | 뜻 |
|---|---|---|
| Switching 값이 있음 | `{플랫폼} 경유` | 커넥터 설정 — OHMY가 코드를 짜지 않음 |
| OHMY Dev Load = Full / Half | `OHMY 직접` | 우리가 구현 |
| 그 외 (Minimal / None) | `파트너 구현` | 파트너가 우리 API에 붙음. 우리는 키·스펙·질의 대응 |

**단계별 다음 액션**은 사내 API 연동 프로세스 9단계를 그대로 따릅니다.

| 진행률 | 다음 할 일 | 담당 |
|---|---|---|
| 0% Contact | 계정 발급 · Top-Selling 리스트 · 3~6주 Follow-up | GSM |
| 20% NDA | 적합성 5문항 (채널·B2B 비중·일 주문량·공급방식·통화) | GSM |
| 30% Contract | Deposit·Credit Ratio·Settlement·Currency 합의 → 승인 | SLA |
| 40% SLA | **DEV Credential 발급 · API SPEC · DEV 환경 URL** | 개발 |
| 45% Kickoff | 고객사 IT 명단·IP 확보 → Teams 채널 개설 | 개발 |
| 50% Dev Kickoff | 테스트 시나리오 배포 · Certification · Static 갱신 | 경로에 따름 |
| 60% Certification | Cert 문서·Log 검증 → Pass 판정 | 경로에 따름 |
| 70% Live Test | **라이브키 발급** → 실거래 부킹 검증 | 개발 |
| 75% Dev 완료 | 부킹 기록 확인 · Go-Live D-Day 통보 | 개발 |
| 80% Live Open | D-7 모니터링 시프트 · D-Day 대기 | 개발 |
| 90% First Booking | 에러율·취소율 모니터링 · 주간 데이터 공유 | 개발 |

**키 발급(40·45·70·75)과 런칭 모니터링은 구현 주체와 무관하게 항상 OHMY 개발팀**입니다. 구현(50·60)만 경로를 따릅니다.
60~70% 구간에는 **라이브키는 Cert Pass + Deposit 입금 둘 다 충족해야 발급**이라는 게이트가 함께 표시됩니다.

**모니터링 컬럼** — "담당자가 누구냐"가 아니라 **개발팀이 지금 어느 강도로 보고 있어야 하는가**를 표시합니다.
세일즈는 어차피 전 건을 보고 있으니, 개발팀 기준으로만 눈금을 매겼습니다.

| 표시 | 뜻 | 언제 |
|---|---|---|
| **개발 대응** (빨강) | 개발팀이 산출물을 내야 함 | 40·45(DEV 키) · 70·75(라이브키) · 80·90(모니터링) · 50·60 중 OHMY 직접 |
| **개발 확인** (주황) | 남이 구현하지만 검수 필요 | 50·60 중 스위칭 경유 |
| **개발 대기** (파랑 테두리) | 파트너 구현 대기, 질의 대응 | 50·60 중 파트너 구현 |
| **개발 사전 인지** (보라 테두리) | 아직 영업 단계지만 **공수 큰 건이 오고 있음** | 0·20·30 중 Dev Load Full/Half 또는 High Impact |
| 영업 단계 (회색) | 개발 관여 없음 | 그 외 |

`개발 사전 인지`가 "개발팀이 좀 더 신경 쓰라"는 장치입니다. 계약이 끝나고 나서야 알게 되는 대신,
공수가 큰 High Impact 건이 아직 접촉 단계일 때부터 목록에 뜹니다. 지금 10건이 여기 걸려 있습니다.

패널 상단에 `개발 대응 N · 확인 M · 대기 K · 사전 인지 L` 요약이 뜨고,
`전체 / 개발 대응 필요` 토글로 대응·확인 건만 추릴 수 있습니다.

### 나머지 패널

**PIC별 부하** · **카테고리별 현황** · **마지막 활동 경과** · **지금 손봐야 할 10건** — 전부 클릭하면 목록으로 드릴다운됩니다.

### 전체 목록 탭

| | |
|---|---|
| 검색 | 파트너·PIC·카테고리·단계 검색. `/` 키로 포커스, `Esc` 로 해제 |
| 필터 | 상태 · 카테고리 · PIC · **현재 단계** · 활동상태 조합 가능 |
| 정렬 | 컬럼 헤더 클릭 |
| Stage track | 11단계를 칸으로 표시 — 채워진 칸이 날짜가 기록된 단계, 마우스 올리면 날짜 |
| 행 클릭 | 11단계 날짜 전체 펼쳐보기 |
| CSV 내보내기 | 지금 화면에 보이는 것만 (엑셀에서 바로 열림) |

**기본 정렬은 "손이 필요한 순"입니다.** 90일+ 방치 → 30일+ → 14일+ → 기록없음 → 정상 → Live 순으로,
같은 그룹 안에서는 진행률이 높은 것부터. 이미 Live인 건은 오래됐어도 맨 아래로 갑니다 — 멈춘 게 아니라 끝난 것이니까요.

**경과일은 엑셀 값을 쓰지 않고 오늘 기준으로 다시 계산합니다.** 시트의 `Days Elapsed` 가 낡아도 화면은 항상 정확합니다.

색: 14일 이내 회색 · 15~30일 주황 · 31~90일 진한 주황 · 90일 초과 빨강 · 활동기록 없음 빨강 · Live 초록.
다크모드는 OS 설정을 따라갑니다. 탭 상태는 주소창 `#dashboard` / `#list` 로 남아서 링크 공유가 됩니다.

## 파일 구성

```
index.html            화면 구조
styles.css            스타일
app.js                필터 · 정렬 · 검색 · CSV
data/
  Dev_Schedule.xlsx   ← 원본. 이것만 교체하면 됨
  tracker.js          자동 생성 — 화면이 읽는 파일
  tracker.json        자동 생성 — 다른 도구에서 쓸 원본 데이터
i18n.js               한국어 / English 문구
scripts/build.mjs     엑셀 → JSON 변환기
scripts/serve.mjs     로컬 미리보기 (npm run preview)
update.bat            더블클릭용
```

`tracker.js` / `tracker.json` 은 자동 생성물이지만 **커밋해 두세요.** 그래야 clone 하거나
폴더를 복사한 사람이 아무것도 실행하지 않고 바로 볼 수 있습니다.
